#### Migration System
**File:** `dist/js/planner-db.js:50-200`

```javascript
const TARGET_VERSION = 3; // Current schema version

const MIGRATIONS = {
  1: `CREATE TABLE tbl_building ...`, // DEPRECATED (unused)
  2: `CREATE TABLE planner_state ...
      CREATE TABLE planner_subnet ...`,
  3: `ALTER TABLE planner_subnet ADD COLUMN vlan_id ...
      ALTER TABLE planner_subnet ADD COLUMN gateway_ip ...
      CREATE TABLE planner_vrf ...`
};

async runMigrations() {
  const currentVersion = this.db.exec('PRAGMA user_version;')[0].values[0][0];
  for (let v = currentVersion + 1; v <= TARGET_VERSION; v++) {
    this.db.exec(MIGRATIONS[v]);
    this.db.exec(`PRAGMA user_version = ${v};`);
  }
}
```

**Agent Rule (Schema Manager):**
- Always increment TARGET_VERSION when adding migration
- New migration number = TARGET_VERSION + 1
- Update `app/database-schema.md` after migration changes
- Update test expectations in `src/tests/planner-basics.spec.ts`

#### Snapshot Persistence
**File:** `dist/js/main.js:1450-1600`

| Function | Lines | Purpose | Triggered By |
|----------|-------|---------|--------------|
| `schedulePlannerSnapshotPersist()` | 1450-1470 | Debounce DB writes (500ms delay) | mutate_subnet_map |
| `persistPlannerSnapshot()` | 1480-1550 | Serialize subnetMap to DB rows | Debounce timer |

**Serialization Logic:**
1. `subnetMap` (nested object) → Flatten to `planner_subnet` rows with `parent_id`
2. Extended fields: `_vlan`, `_gateway`, `_vrf`, `_capacityTotal` → DB columns
3. Tree traversal: Recursive depth-first walk, assign ordinal for deterministic ordering

**Deserialization Logic:**
1. Query `SELECT * FROM planner_subnet ORDER BY ordinal`
2. Build subnetMap tree by linking children to parents via `parent_id`
3. Hydrate extended fields from DB columns

#### Operating Mode Rules
**File:** `dist/js/main.js:50-62`

```javascript
const minSubnetSizes = {
  Standard: 32,  // /32 allowed (single host)
  AZURE: 29,     // /29 minimum (Azure reserves 5 IPs)

  OCI: 30        // /30 minimum (OCI reserves 3 IPs)

  Standard: '^([12]?[0-9]|3[0-2])$',  // /0 to /32
  AZURE: '^([12]?[0-9])$',            // /0 to /29
```

**Reserved IP Logic by Mode:**
- **Standard:** Network (first), Broadcast (last) = 2 reserved
- **AWS:** Network + 3 reserved (VPC router, DNS, future) + Broadcast = 5 reserved
- **Azure:** Network + 3 reserved (gateway, DNS×2) + Broadcast = 5 reserved
- **OCI:** Network + 1 reserved (gateway) + Broadcast = 3 reserved

### Undo/Redo System

#### History Management
**File:** `dist/js/main.js:1600-1750`

| Function | Lines | Purpose |
|----------|-------|---------|
| `saveHistorySnapshot(action, desc)` | 1610-1650 | Capture current state before mutation |
| `undo()` | 1680-1710 | Restore previous state, move position back |
| `redo()` | 1720-1750 | Restore next state, move position forward |

**History Stack Structure:**
```javascript
historyStack = [
  {
    timestamp: '2025-10-01T12:00:00Z',
    action: 'split',
    description: 'Split 10.0.0.0/24 into /25',
    state: {
      subnetMap: { /* snapshot */ },
      subnetNotes: { /* snapshot */ },
      operatingMode: 'Standard'
    }
  },
  // ... more snapshots
];

historyPosition = 2; // Current position (0-indexed)
maxHistorySize = 50; // Limit to prevent memory bloat
```

**Undo/Redo Flow:**
1. Before mutation: `saveHistorySnapshot(action, description)`
2. User clicks Undo: `undo()` → restore `historyStack[historyPosition - 1].state`
3. User clicks Redo: `redo()` → restore `historyStack[historyPosition + 1].state`
4. New action after undo: Truncate stack at current position, append new snapshot

**Agent Rule:** Call `saveHistorySnapshot()` BEFORE every state mutation to enable undo.

### Task 1: Add New Subnet Metadata Field

**Example:** Add "purpose" field (LAN, MGMT, INTERCONNECT, OTHER)

**Navigation Path:**
1. **Schema (Schema Manager):**
   - File: `dist/js/planner-db.js:50-200`

   - File: `dist/js/main.js:1560-1600`
   - Function: `hydratePlannerFromSnapshot()`
   - Action: Map `row.purpose` to `subnet._purpose`

3. **Persistence (Dist Agent):**
   - File: `dist/js/main.js:1480-1550`
   - Function: `persistPlannerSnapshot()`
   - Action: Include `purpose: subnet._purpose || 'LAN'` in INSERT

4. **UI (Dist Agent):**
   - File: `dist/index.html:250-300`
   - Action: Add `<th>Purpose</th>` to table headers
   - File: `dist/js/main.js:550-700`
   - Function: `_renderRow()`
   - Action: Add `<td><select class="purpose-select" data-subnet="${cidr}">...</select></td>`

5. **Event Handling (Dist Agent):**
   - File: `dist/js/main.js:88-250`
   - Action: Add `$('#calcbody').on('change', '.purpose-select', function() { mutate_subnet_map('purpose', cidr, '', $(this).val()); })`

6. **Tests (Src Agent):**
   - File: `src/tests/planner-snapshot.spec.ts`
   - Action: Add test for purpose field persistence

7. **Docs:**
   - File: `app/database-schema.md`
   - Action: Document `purpose` column

- Schema Manager → Dist Agent (requires migration first)

### Task 4: Optimize Performance

**Example:** Reduce renderTable() time for 1000+ subnets

**Navigation Path:**
1. **Profile (Dist Agent):**
   - File: `dist/js/main.js:420-520` (`renderTable()`)
   - Measure: Time spent in DOM clear and rebuild

2. **Identify Bottleneck (Dist Agent):**
   - Likely cause: `$('#calcbody').empty()` + full tree walk

3. **Optimize (Dist Agent):**
   - Strategy: Incremental updates instead of full clear
   - Approach: Track changed subnets, only re-render affected rows

4. **Test Performance (Src Agent):**
   - File: `src/tests/performance.spec.ts`
